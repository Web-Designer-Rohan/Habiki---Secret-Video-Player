Hibiki Feature Specification

Purpose

This document tracks all planned, implemented, and future features of Hibiki.

Features are grouped by category and development status.

Version 1 prioritizes a polished, stable, and maintainable experience over feature quantity.

---

Version 1 Core Features

Authentication

Status: Complete

Features:

- Single local password gate (scrypt hashed)
- Startup bootstrap password written to config/initial-admin.txt (delete after first unlock)
- Unlock / lock / change password endpoints
- Brute-force protection (5 failed attempts → 15-minute lockout per client)

---

Library

Status: Complete

Features:

- Filesystem-driven library (single media root, default `contents/`)
- Six automatic categories: Anime, Movies, Tutorials, Other, TV Shows, Courses
- Season selection and episode selection (Anime)
- Standalone titles with one-click play (Movies / Tutorials / Other / TV Shows / Courses)
- Posters and banners per title (poster.* / banner.* in the title folder)
- Episode thumbnails (generated by scripts/generate_thumbnails.py, discovered by the scanner)
- Optional info.json metadata (title, description, year, genre, studio)
- Fast searching (title, episode, season)
- Category filters (All / Anime / Movies / Tutorials / Other / TV Shows / Courses)
- Sorting (canonical order, recently scanned, title A–Z)
- Deterministic, incremental, non-blocking background scans with warnings
- Per-title banner route for the welcome screen

---

Video Player

Status: Complete

Features:

- Custom interface
- Play/Pause
- Seeking
- Volume control
- Fullscreen
- Subtitle selection
- Audio track selection (when available)
- Playback speed
- Resume playback
- Keyboard shortcuts
- Previous / next episode navigation
- Loading indicators and error states

---

Continue Watching

Status: Complete

Features:

- Automatic playback progress
- Resume from last position
- Recently watched list

---

Favorites

Status: Complete

Features:

- Favorite anime
- Quick access
- Favorite persistence

---

Watch History

Status: Complete

Features:

- Recently watched episodes
- Playback timestamps
- Viewing history

---

Teacher Mode

Status: Complete

Purpose:

Provide an immediate alternative reading interface while preserving the current playback state.

Activation:

- Teacher Mode button
- Configurable keyboard shortcut (T / F2 / none)

Features:

- Preserve playback position
- Instant transition
- Return to playback without losing progress
- Optional configured reading page (iframe) or built-in reading copy
- Respects the reduced-motion preference

---

Dashboard

Status: Complete

Administrator features:

- Library overview statistics (Anime / Movies / Tutorials / Other / TV Shows / Courses / Episodes / Posters / Banners)
- Library management
- Metadata editing (title, description, year, genre, studio — persisted to info.json)
- Application settings (media root)
- Background library scan with progress and warnings
- Database refresh (integrity check and dangling-reference pruning)
- Diagnostics (status, health)

Locked clients see a locked notice; unlocking grants full access.

---

Welcome Screen

Status: Complete

Features:

- Random banner from the local collection
- Swipe-up interaction (touch) and button entry
- Smooth Anime.js transition
- Configurable display (every launch / once per session)

---

Background System

Status: Complete

Features:

- Random background from the local banner collection
- Dark overlay
- Bottom-to-top black gradient
- Decorative only; never reduces readability

---

Settings

Status: Complete

User settings:

- Subtitle preference
- Playback speed
- Volume
- Welcome screen preference
- Reduce motion
- Teacher Mode shortcut
- Reading page URL

Administrator settings:

- Media root (folder name or absolute path; default `contents`)
- Application configuration

Settings persist and are applied immediately; they are restored on the next launch.

---

Media Management

Status: Complete

Features:

- Background library scan with status endpoint and warning reporting
- Metadata validation (info.json, episode names, duplicate numbers)
- Missing-file and misplaced-media detection (warnings, never failures)
- Thumbnail generation via scripts/generate_thumbnails.py when FFmpeg is available
- Configuration management (media root)

The scanner pipeline (backend/app/scanner.py + scripts/generate_thumbnails.py) is wired into the dashboard (scan, refresh database).

---

Accessibility

Status: Complete

Features:

- Keyboard navigation (player shortcuts and configured Teacher Mode shortcut)
- Semantic HTML
- Visible focus indicators
- High contrast
- Reduced motion support (media query and in-app setting)

---

Performance

Status: Complete

Goals:

- Fast startup
- Smooth playback
- Efficient rendering
- Low memory usage
- Optimized assets
- Lazy-loaded poster images, debounced search, single-pass server-side search

---

Security

Status: Complete

Features:

- Single-password local authentication (scrypt)
- Unlock rate limiting (5 attempts → 15-minute lockout)
- Security headers (nosniff, frame, referrer, permissions, CSP)
- Cross-origin state-changing request rejection
- Input validation (settings whitelist, path validation, payload models)

---

Deferred Features

These are intentionally postponed beyond Version 1:

- Advanced theme customization
- Plugin system
- Metadata import providers
- Multi-profile enhancements
- Advanced player skins
- Remote control support
- Cloud synchronization

---

Version 1 Definition of Done

Version 1 is complete when:

- Local authentication is operational.
- Mochi and E-Mochi roles function correctly.
- Local media playback is reliable.
- Continue Watching works.
- Favorites work.
- Watch History works.
- The Dashboard is fully functional.
- The custom player is complete.
- Library scanning functions correctly.
- Documentation is synchronized with implementation.
- The application operates fully offline on supported platforms.

---

Feature Philosophy

Every new feature must satisfy the following questions before implementation:

- Does it improve the user experience?
- Does it align with the project vision?
- Can it be maintained long term?
- Does it preserve performance?
- Does it avoid unnecessary complexity?

If the answer is no, the feature should be deferred or rejected.
