Hibiki Feature Specification

Purpose

This document tracks all planned, implemented, and future features of Hibiki.

Features are grouped by category and development status.

Version 1 prioritizes a polished, stable, and maintainable experience over feature quantity.

---

Version 1 Core Features

Authentication

Status: Complete

Features:

- Local login
- Multiple local users
- Role-based access control
- Secure password hashing
- Local session management

Roles:

Mochi (Administrator)

Permissions:

- Manage library
- Manage metadata
- Manage posters
- Manage banners
- Configure application settings
- Manage users
- Run library scans
- Generate thumbnails
- Access maintenance tools
- View application logs

E-Mochi (Member)

Permissions:

- Watch media
- Continue Watching
- Favorites
- Watch History
- Subtitle selection
- Audio selection (future)
- Playback settings
- Language selection

Members cannot modify the media library or application configuration.

---

Library

Status: Complete

Features:

- Automatic library scanning
- Anime browsing
- Season selection
- Episode selection
- Posters
- Episode thumbnails
- Local metadata
- Fast searching (title, episode, season, tutorial)
- Filters (All / Series / Tutorials)
- Sorting (order added, recently added, title A–Z)
- Season and episode browsing in the library UI

---

Video Player

Status: Complete

Features:

- Custom interface
- Play/Pause
- Seeking
- Volume control
- Fullscreen
- Subtitle selection
- Audio track selection (when available)
- Playback speed
- Resume playback
- Keyboard shortcuts
- Previous / next episode navigation
- Loading indicators and error states

---

Continue Watching

Status: Complete

Features:

- Automatic playback progress
- Resume from last position
- Recently watched list

---

Favorites

Status: Complete

Features:

- Favorite anime
- Quick access
- Favorite persistence

---

Watch History

Status: Complete

Features:

- Recently watched episodes
- Playback timestamps
- Viewing history

---

Teacher Mode

Status: Complete

Purpose:

Provide an immediate alternative reading interface while preserving the current playback state.

Activation:

- Teacher Mode button
- Configurable keyboard shortcut (T / F2 / none)

Features:

- Preserve playback position
- Instant transition
- Return to playback without losing progress
- Optional configured reading page (iframe) or built-in reading copy
- Respects the reduced-motion preference

---

Dashboard

Status: Complete

Administrator features:

- Library overview statistics
- Library management
- Metadata editing (anime title, description, poster, banner)
- Episode title editing
- Localization editor (hi / en / ja)
- User management
- Application settings (media folders, language)
- Library scan
- Database refresh (integrity check and dangling-reference pruning)
- Diagnostics (status, health)

E-Mochi members see a locked notice; Mochi administrators get full access.

---

Welcome Screen

Status: Complete

Features:

- Random banner from the local collection
- Swipe-up interaction (touch) and button entry
- Smooth Anime.js transition
- Configurable display (every launch / once per session)

---

Background System

Status: Complete

Features:

- Random background from the local banner collection
- Dark overlay
- Bottom-to-top black gradient
- Decorative only; never reduces readability

---

Localization

Status: Complete

Languages:

- Hindi
- English
- Japanese

Switching language updates the interface without restarting, persists per user, and is editable by administrators in the dashboard. Future languages should be easy to add.

---

Settings

Status: Complete

User settings:

- Language
- Subtitle preference
- Playback speed
- Volume
- Welcome screen preference
- Reduce motion
- Teacher Mode shortcut
- Reading page URL

Administrator settings:

- Library paths
- Application configuration

All settings persist per user and are applied on the next launch.

---

Media Management

Status: Complete

Features:

- Library scan
- Metadata validation
- Missing file detection
- Thumbnail generation
- Configuration management

The asset and validation pipeline (scripts/import_assets.py, build_library.py, generate_thumbnails.py, validate_library.py, project_size.py) is implemented and wired into the dashboard (scan, refresh database). Thumbnails are generated by scripts/generate_thumbnails.py when FFmpeg is available.

---

Accessibility

Status: Complete

Features:

- Keyboard navigation (player shortcuts, Escape exits Teacher Mode)
- Semantic HTML
- Visible focus indicators
- High contrast
- Reduced motion support (media query and in-app setting)

---

Performance

Status: Complete

Goals:

- Fast startup
- Smooth playback
- Efficient rendering
- Low memory usage
- Optimized assets
- Lazy-loaded poster images, debounced search, single-pass server-side search

---

Security

Status: Complete

Features:

- Local authentication
- Role-based authorization (Mochi / E-Mochi)
- scrypt password hashing
- Input validation
- HttpOnly SameSite session cookies with expiry

---

Deferred Features

These are intentionally postponed beyond Version 1:

- Theme customization
- Plugin system
- Metadata import providers
- Multi-profile enhancements
- Advanced player skins
- Additional localization
- Remote control support
- Cloud synchronization

Feature Status Legend

- Planned
- In Progress
- Complete

Every feature should move through these states during development.

---

Version 1 Definition of Done

Version 1 is complete when:

- Local authentication is operational.
- Mochi and E-Mochi roles function correctly.
- Local media playback is reliable.
- Continue Watching works.
- Favorites work.
- Watch History works.
- The Dashboard is fully functional.
- The custom player is complete.
- Library scanning functions correctly.
- Documentation is synchronized with implementation.
- The application operates fully offline on supported platforms.

---

Feature Philosophy

Every new feature must satisfy the following questions before implementation:

- Does it improve the user experience?
- Does it align with the project vision?
- Can it be maintained long term?
- Does it preserve performance?
- Does it avoid unnecessary complexity?

If the answer is no, the feature should be deferred or rejected.
